# Навигатор обновлений

Навигатор решает две разные задачи: пользователь узнаёт о новой версии, а
обновление применяется без ручного скачивания ZIP и повторной настройки машины.

## Каналы

### stable

Канал по умолчанию. Проверяется последний GitHub Release. Пользователь получает
уведомление только когда номер версии выше установленного.

Используйте stable для коллег и обычных рабочих машин.

### main

Проверяется HEAD ветки `main`. Любой новый commit считается обновлением.

Используйте main на тестовой машине, если нужно получать изменения сразу после
push, не дожидаясь Release.

Канал задаётся при установке:

```powershell
.\scripts\install.ps1 -UpdateChannel stable
.\scripts\install.ps1 -UpdateChannel main
```
## Что происходит на машине

Установщик копирует `check-update.ps1` и `update.ps1` в
`%LOCALAPPDATA%\RdcWorkstationHarness\maintenance` и создаёт
`install-state.json` с установленной версией, commit SHA и настройками.

Задача `RDC Harness - Update Check` запускается при входе в Windows и ежедневно
в 10:00. Проверка использует публичный GitHub API и не требует GitHub token.

Если найдено обновление:

1. создаётся `update-available.json`;
2. Windows показывает уведомление;
3. один и тот же релиз не уведомляет повторно;
4. пользователь запускает `maintenance\update.ps1`.

Отключить автоматическую проверку:

```powershell
.\scripts\install.ps1 -NoUpdateCheck
```

Ручная проверка:

```powershell
& "$env:LOCALAPPDATA\RdcWorkstationHarness\maintenance\check-update.ps1"
```
## Применение обновления

```powershell
& "$env:LOCALAPPDATA\RdcWorkstationHarness\maintenance\update.ps1"
```

Updater:

- скачивает source archive выбранного канала;
- делает ZIP-бэкап текущего runtime, включая установленные зависимости;
- повторно запускает installer с сохранёнными портами, браузером, каналом и RDC;
- сохраняет локальные tokens, browser profile и device identity;
- при ошибке восстанавливает предыдущий runtime из backup и перезапускает прежние службы.

Обновление запускается только пользователем: фоновая задача сообщает о новой
версии, но не выполняет скачанный код. Перед запуском `update.ps1` проверьте
страницу релиза и список изменений. Архив принимается только из настроенного
GitHub-репозитория; как и при первой установке, исходникам этого репозитория
нужно доверять.

Бэкапы лежат в
`%LOCALAPPDATA%\RdcWorkstationHarness\backups`.

## Как выпускать обновление

Для stable-канала:

1. изменить код;
2. обновить `VERSION`, например `0.1.0 -> 0.1.1`;
3. дополнить `CHANGELOG.md`;
4. прогнать CI;
5. смержить в `main`;
6. создать GitHub Release с тегом `v0.1.1`.

Для main-канала достаточно push в `main`. Пользователь увидит новый commit при
следующей проверке. Это быстрее, но менее предсказуемо, поэтому для коллег
лучше stable.
