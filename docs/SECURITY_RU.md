# Модель угроз и безопасность

## Предположения

Harness рассчитан на доверенный Windows-ПК и доверенную учётную запись.
Пользователь понимает, что локальный агент способен управлять программами и
выполнять команды с его обычными правами.

Не предполагается:

- общий сервер для нескольких неизвестных пользователей;
- прямой доступ к портам harness из сети;
- работа на терминальном сервере с недоверенными соседними сессиями;
- использование токена как замены полноценной сетевой аутентификации;
- скрытая установка или работа без ведома владельца ПК.

## Защищаемые данные

- desktop/browser tokens;
- идентичность Remote Commander конкретного устройства;
- cookies и storage state отдельного браузерного профиля;
- содержимое файлов, окон и буфера обмена;
- права активных COM/API-сессий приложений;
- локальные logs и создаваемые artifacts.
## Основные меры

### Loopback only

Desktop Agent и Browser Bridge слушают только `127.0.0.1`.
Это намеренное ограничение кода, а не рекомендуемая настройка. Не меняйте bind
на `0.0.0.0` и не публикуйте порты 17321–17322 через port forwarding.

### Раздельные токены

Desktop и browser используют разные токены. Они создаются локально,
не выводятся установщиком и исключены из Git. `-RotateTokens` меняет оба токена.

### Минимум физического ввода

UIA, Playwright, COM и native API предпочтительнее. Движение мыши и ввод с
клавиатуры требуют явного разрешения конкретного action. У PyAutoGUI сохранён
аварийный failsafe.

### Предохранитель внешних действий

`tools/rdc_web.py` помечает клики с признаками отправки, публикации, покупки,
удаления или подтверждения и требует `--commit`. Это дополнительный слой, а не
полная семантическая защита: вызывающая сторона всё равно должна различать
чтение, подготовку черновика и внешнее действие.
## Компонентные риски

### Browser Bridge

Токен Bridge фактически даёт управление сессиями отдельного профиля. Не входите
в нём в лишние аккаунты, не используйте тот же профиль для повседневного
браузинга и не публикуйте storage state. Для особо чувствительного аккаунта
лучше использовать отдельную Windows-учётную запись или не подключать его вовсе.

### Remote Desktop Commander

Remote Commander использует собственное сопряжение устройства. Каталог
`.desktop-commander-device` принадлежит одному ПК и одной регистрации. Перенос
этого каталога нарушает границу доверия; коллега должен создать свою identity.

### Logs и artifacts

Журналы могут содержать URL, названия окон, пути и параметры операций. Не
коммитьте runtime-каталоги. Перед передачей diagnostic bundle просмотрите его и
удалите личные/корпоративные данные.
## Чек-лист перед рабочим использованием

1. `diagnose.ps1` не показывает listener на внешнем интерфейсе.
2. На компонент приходится ровно одна задача автозапуска.
3. Токены и профили отсутствуют в `git status`.
4. Browser Bridge содержит только нужные аккаунты.
5. Физический ввод остаётся выключенным по умолчанию.
6. Внешние действия подтверждаются отдельно от чтения/подготовки.
7. Для действий в приложениях есть backup и понятный rollback.

## При подозрении на раскрытие локальных данных

```powershell
.\scripts\stop.ps1 -IncludeRemoteCommander
.\scripts\install.ps1 -RotateTokens -SkipStart
```

После этого:

- выйдите из затронутых browser sessions;
- удалите локальный браузерный профиль, если нужно начать с нуля;
- заново выполните pairing Remote Commander, если затронута identity;
- проверьте журналы и историю подключённых клиентов;
- запустите harness и повторите диагностику.

## Корпоративное развёртывание

Для масштабирования на несколько ПК нужен отдельный проект управления
конфигурацией: централизованный секрет-хранилище, allow-list клиентов, аудит,
версии политик и разграничение ролей. Этот репозиторий намеренно остаётся
single-workstation harness и не выдаёт локальный token за enterprise security.
